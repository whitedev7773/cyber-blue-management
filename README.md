# Aegis Review

파일 기반 방어 검토 대시보드 MVP. 설정 파일을 주제별 로컬 작업자가 병렬 점검하고, 근거·조건·수정 제안·검토 이력을 한곳에서 관리합니다.

> **현재 구현 범위**: 고정된 7개 설정 기준과 SARIF 보고서 가져오기입니다. 소스코드 전체 취약점 탐지, 실제 LLM 서브 에이전트, 다중 모델 연결, 자동 패치 적용은 구현되어 있지 않습니다. `completed`는 계획된 처리가 끝났다는 의미이며 안전 판정이 아닙니다.

## 실행

Python 3.11 이상. 별도 Python 패키지나 프런트엔드 빌드가 필요 없습니다.

```bash
python -m aegis.server
```

브라우저에서 http://127.0.0.1:8765 를 열고 **예제 분석 시작**을 누르세요. 예제는 설정 편차 4개, 기준 통과 3개를 생성합니다.

```bash
python -m aegis.server --port 9000 --data .aegis/reviews.sqlite3
python -m unittest discover -s tests -v
```

Windows에서는 `python` 대신 `py -3`를 사용할 수 있습니다. 반드시 프로젝트 루트에서 실행하세요. 서버는 로컬 루프백에만 바인딩하며, 공용 서비스 배포용 서버가 아닙니다.

## 구현된 기능

- 단일 파일 / ZIP / SARIF 2.1.0 업로드
- 3개 주제 팀, 6개 전문 작업, 최대 3개 병렬 작업자
- 세션 쿠키·유휴 만료, HTTPS·브라우저 헤더, 디버그·감사 로그 점검
- 설정 편차 / 맥락 부족 / 외부 미검증 판정 분리
- 파일 경로 + JSON Pointer 근거, 기준 재검사, JSON Patch 제안
- 발견 사항 수용·보류·기각·미검토 상태와 변경 이력
- 전체 JSON 보고서 및 개별 JSON Patch 다운로드
- SQLite 실행 이력과 삭제, 서버 재시작 시 중단된 작업 실패 표시
- 한국어 반응형 대시보드, 분석 범위 및 미지원 파일 표시
- 실행당 6개 이하 전문 작업, 전체 동시 분석 2개 제한

## 지원 입력

### security.config.json

파일명이 정확히 `security.config.json`인 JSON 객체를 검사합니다. ZIP 내부의 하위 디렉터리에도 둘 수 있습니다. 이 형식은 **앱 자체의 선언형 점검 계약**이며 Django·Express 등의 설정을 자동 변환하지 않습니다. 실제 서비스와 일치하도록 값을 작성해야 합니다.

아래는 정책에 부합하는 예시입니다. 이 파일만으로 실제 런타임 설정이 변경되지는 않습니다.

```json
{
  "session": {
    "cookieSecure": true,
    "cookieHttpOnly": true,
    "idleTimeoutMinutes": 30
  },
  "transport": {"httpsOnly": true},
  "headers": {"nosniff": true},
  "runtime": {"debug": false},
  "logging": {"auditEnabled": true}
}
```

30분 유휴 만료는 MVP의 예시 조직 기준입니다. 모든 서비스에 보편적으로 적합한 수치가 아닙니다. 키가 없거나 자료형이 잘못되면 `needs_context`로 분류하고 패치를 제안하지 않습니다. 설정 편차도 실제 취약점으로 확정하지 않습니다.

### ZIP

메모리에서 읽고 디스크에 압축 해제하지 않습니다. 최대 업로드 4 MiB, 개별 파일 512 KiB, 압축 해제 총량 12 MiB, ZIP 항목 250개입니다. 절대 경로·상위 경로·심볼릭 링크·중복 경로·암호화 ZIP을 거부합니다. 일반 소스코드는 목록에 기록하고 미지원으로 표시합니다.

### SARIF

`.sarif` 파일의 2.1.0 결과를 가져옵니다. 규칙 ID와 결과 수준만 사용합니다. 원본 메시지·코드 조각·위치는 복사하지 않으므로 상세 검토에는 원본 보고서가 필요합니다. 모든 가져온 결과는 `external_unverified`입니다. 실행당 전체 2,000개, 파일당 1,000개 결과를 제한합니다.

## 수정안 의미

JSON Patch는 특정 파일의 특정 JSON Pointer에 대한 **검토용 제안**입니다. 선택한 패치의 다운로드 파일에는 연산 배열만 포함되므로 대상 파일은 화면이나 전체 보고서에서 확인하세요.

앱은 원본을 수정하지 않습니다. 패치 적용, 빌드, 기능 회귀, 운영 상태를 검증하지 않습니다. `accepted`는 사용자가 발견 사항을 수용했다는 뜻이며 수정 완료가 아닙니다. 동일 규칙을 다시 평가한 결과를 '규칙 재검증'이라 부르며 독립 모델 검증으로 표시하지 않습니다.

## 데이터와 실행 경계

- 업로드 원본은 작업 중 메모리에만 보유하며 프로그램을 실행하지 않습니다.
- DB에는 파일명·경로·크기·SHA-256·발견·검토 이력이 남습니다. 설정 원문과 임의 설정값은 저장하지 않습니다.
- 파일명과 SARIF 규칙 ID는 업로드에서 온 메타데이터입니다. 민감한 이름을 사용하지 마세요.
- 네트워크 요청, 모델 API 호출, 텔레메트리는 없습니다.
- 로컬 Host 검사, 동일 출처 검사, 변경 요청 토큰, CSP를 적용합니다.
- 단일 로컬 사용자용입니다. 같은 OS 사용자와 다른 로컬 프로세스로부터 데이터를 격리하지 않습니다.
- UI 삭제는 논리적 레코드 삭제입니다. SQLite·파일시스템의 포렌식 보안 삭제를 보장하지 않습니다.

## 프로젝트 구조

| 경로 | 역할 |
| --- | --- |
| `aegis/engine.py` | 입력 제한, 고정 정책, 병렬 전문 작업, SARIF 가져오기 |
| `aegis/server.py` | 로컬 HTTP API, 작업 접수, SQLite 이력 |
| `web/` | 외부 의존성 없는 한국어 대시보드 |
| `examples/` | 설정 및 SARIF 예제 |
| `tests/` | 입력 경계·점검 결과·API·이력 테스트 |
| `docs/architecture.md` | 구현 구조와 후속 확장 경계 |
| `scripts/publish_github.py` | GitHub CLI를 통한 비공개 저장소 생성·푸시 |

## GitHub에 게시

GitHub CLI가 설치되어 있고 `gh auth login`이 완료된 환경에서:

```bash
python scripts/publish_github.py --name aegis-review
```

기본은 비공개 저장소입니다. 공개를 원하면 명시적으로 `--public`을 추가합니다. 기존 `origin`이 있거나 동일 이름 저장소가 있으면 덮어쓰지 않고 중단합니다. Git 커밋 작성자 정보가 없으면 `git config user.name` 및 `git config user.email`을 먼저 설정하세요.

## 검증

- Python 표준 `unittest` 24개 통과
- 프런트엔드 `node --check web/app.js` 통과
- 실제 HTTP 서버 기반 업로드 → 분석 → 검토 변경 → 삭제 통합 테스트 포함
- 이 제작 환경에는 Chromium 실행 파일이 없어 실제 브라우저 시각·상호작용 테스트는 수행하지 못했습니다.
- GitHub Actions 설정 포함. 원격 저장소 게시 전이므로 원격 CI는 아직 실행되지 않았습니다.
